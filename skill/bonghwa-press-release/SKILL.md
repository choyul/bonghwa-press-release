# 봉화군 보도자료 작성 기준

## 언제 쓰나

다음 요청에 발동한다.
- 보도자료 초안을 쓰거나 다듬어 달라는 요청
- 발표덱·기획안·용역 산출물 같은 원자료를 보도자료로 요약해 달라는 요청
- 공보팀 제출용 양식(hwp 또는 hwpx)을 채워 달라는 요청
- 기존 보도자료 문안을 고쳐 달라는 요청

## 작업 순서

1. 원자료를 읽는다(아래 "원자료 요약").
2. 보도자료 초안을 대화창에 먼저 보여 주고, 확인이 필요한 항목을 따로 나눠 적는다.
3. 사용자가 양식을 주면 양식에 채워 파일로 만든다(아래 "양식 채우기"). 양식이 없으면 초안 끝에 "양식을 주시면 채워 드립니다"라고 한 줄로 알린다.

## 원자료 요약

첨부 파일은 실제로 열어서 읽은 내용만 쓴다. pptx는 텍스트를 뽑고, 필요하면 이미지로 렌더링해 장표 구조를 확인한다. PDF는 전문을 뽑은 뒤 핵심 쪽만 이미지로 확인한다.

원자료에서 기사에 쓸 사실(무엇을, 언제, 어디서, 규모, 운영 방식, 일정)을 먼저 추린다. 장표의 소제목이나 "SO WHAT" 같은 내부 보고용 문구는 기사 문장으로 바꿔 쓴다.

다음 항목은 원자료에 있어도 기사에서 뺀다.
- 공개 시점이 걸린 내용: 원자료에 "승인 이후 공개", "확정 전", "검토본", "판매가 미정"처럼 적힌 것
- 기준 시점이나 출처가 없는 통계(인구 수치 등)
- 용역사명, 참여 업체 상호, 개인 실명

원자료끼리 설명이 어긋나면 하나를 임의로 고르지 않고 확인 필요 항목에 적는다. 같은 시설의 준공 시기나 면적이 자료마다 다른 경우가 그렇다. 특정 시설 하나를 다룬 자료의 설명을 여러 시설 전체로 넓혀 쓸 때도 그 사실을 알린다.

시설의 주소나 위치를 넣을 때는 출처(기사, 공고, 대장)를 확인하고, 계획 단계 자료라면 실제 주소와 다를 수 있다고 알린다.

## 문체

신문 기사체(평서형 종결: `~했다`, `~한다`, `~할 계획이다`)로 쓴다. 공문 경어체(`~합니다`)는 쓰지 않는다.

"함께 만들어가는", "~의 여정", "새로운 가치를 창출", "지속 가능한 미래" 같은 AI식·홍보식 상투어는 쓰지 않는다. 담당 주무관이 실제로 쓰는 표현으로 쓴다.

단문을 여러 개 끊어 나열하지 않는다. 연결어미와 지시어로 이어 붙인 문장을 쓴다(예: "지상 3층 규모의 ○○는 ~하도록 층을 구성해, ~로 운영된다").

본문 문단 앞에 □ 등 글머리표를 붙이지 않는다. 양식 안내문에 글머리표를 쓰라고 적혀 있어도 붙이지 않는다.

인용부호는 양식의 기존 문안처럼 둥근 따옴표(‘ ’, “ ”)를 쓴다.

## 구조

제목 → 부제 → 리드 문단 → 본문 → 관계자 코멘트 순서로 쓴다.

제목은 "봉화군, ~" 형식으로 한 줄에 쓴다. 부제는 양식 관례대로 앞뒤에 하이픈을 붙인다("-○○, ○○-").

리드 문단은 무엇을 했는지만 한 문장으로 밝힌다. 이어지는 문단은 대상·기간·방식, 참여 전문가, 세부 지원 내용, 상위 사업과의 관계 순으로 전개한다. 시설을 소개하는 기사라면 다음 순서로 쓴다.
1. 이름과 취지, 위치 관계
2. 시설별 소개(시설당 한 문단)
3. 운영 주체와 일정
4. 연계 플랫폼

본문은 관계자 코멘트를 빼고 6문단 안팎으로 제한한다. 같은 사실을 두 문단에서 반복하지 않는다. "전문가가 매장을 방문한다", "의견을 듣고 과제를 도출한다" 같은 문장이 여러 문단에 흩어져 있으면 한 곳으로 합친다.

마지막 문단의 일반론("앞으로도 ~ 지속할 방침이다", "지역민에게는 ~ 관광객에게는 ~")은 지운다. 기자가 잘라내는 부분이고 사업 정보가 없다.

준공·개소·개관 같은 시점 표현은 배포일 기준 시제로 맞춘다. 배포일에 이미 지난 일이면 "~했다", 아직이면 "~할 예정이다"로 쓰고, 일정이 바뀔 가능성이 있으면 알린다.

## 실명·수치 처리

참여 업체 상호는 쓰지 않는다. "관내 카페·음식점 5개소"처럼 업종과 개소 수로 쓴다. 업종 구성을 모르면 추정하지 말고 확인 필요 항목으로 남긴다.

외부 전문가·강사의 성명, 소속 회사명, 직위는 쓰지 않는다. "식품·외식 대기업에서 19년간 메뉴개발을 담당한 전문가"처럼 경력의 성격만 남긴다. 다만 익명화하면서 전문성의 근거까지 사라지면 안 되므로, 그 경력이 이번 사업과 어떻게 연결되는지 한 문장을 덧붙인다.

위탁 운영 단체명은 확정 전이면 "마을관리사회적협동조합"처럼 일반 표현으로 쓰고, 정식 명칭을 써도 되는지 확인을 요청한다.

용역사나 업체가 제공한 수치(개발 건수, 실적 등)는 검증 근거가 없으면 넣지 않는다. 꼭 넣어야 하면 근거 자료를 확보해야 한다고 함께 알린다.

관계자 코멘트는 직접 지어 넣되, 예시임을 밝히고 발언자와 문구를 확정해야 한다고 알린다.

## 사업명 표기

봉화군 로컬 브랜드는 '찐로컬'로 붙여 쓴다. 공모요강이나 계약서상 정식 명칭이 다를 수 있으므로, 표기가 갈리면 확인을 요청한다. 브랜딩 검수 전인 시설 명칭은 표기가 확정됐는지 확인 필요 항목에 넣는다.

## 양식 채우기

### 1. 파일 형식 확인

봉화군 보도자료 양식은 이전 보도자료 파일을 그대로 쓰는 경우가 많고, 대개 구형 .hwp(HWP 5.0 바이너리)다. 구형 .hwp는 직접 고치지 않고 .hwpx로 바꾼 뒤 채운다.
- 한글이 있으면: [다른 이름으로 저장 → 파일 형식 HWPX]로 저장한다.
- 한글이 없는 환경(Java 17+, Maven, git 필요)이면 변환 도구를 쓴다.

```bash
tools/hwp2hwpx/convert.sh 양식.hwp 양식.hwpx
```

결과물은 .hwpx이며 한글에서 그대로 열린다. .hwp가 필요하면 한글에서 다시 저장하면 된다는 점을 사용자에게 알린다.

### 2. 양식 구조 확인

```bash
pip install lxml
python scripts/fill_hwpx.py --template 양식.hwpx --dump
```

배포일자(예: "9. 8.(월)"), 제목, 부제("-…-"), 본문 문단 목록이 제대로 잡히는지 확인한다. 봉화군 양식의 구조는 다음과 같다.
- 첫 문단 안의 표: 보도자료 머리, 배포일자, 담당자 표, "군정홍보에 많은 관심과 협조 감사드립니다.", 제목, 부제
- 표 다음: 빈 문단과 본문 문단이 번갈아 나온다

### 3. 내용 채우기

내용을 JSON으로 저장한 뒤 실행한다.

```json
{
  "date": "10. 7.(수)",
  "title": "봉화군, ○○ 착수",
  "subtitle": "-○○, ○○-",
  "body": ["리드 문단", "둘째 문단", "…", "관계자 코멘트"]
}
```

```bash
python scripts/fill_hwpx.py --template 양식.hwpx --content 내용.json --out 보도자료_주제.hwpx
```

스크립트가 처리하는 일은 다음과 같다.
- 본문 문단 수에 맞춰 문단을 늘리거나 줄이고, 빈 문단을 사이사이 넣어 원본 간격을 유지한다.
- 본문은 기본 글자 모양 하나로 통일한다. 원본의 자간 조정용 글자 모양은 지운다.
- 텍스트를 바꾼 문단마다 줄 배치 캐시(linesegarray)를 지워 글자 겹침을 막는다.
- mimetype을 비압축으로 맨 앞에 넣어 다시 묶은 뒤, zip 손상 여부를 검사한다.

스크립트를 쓰지 않고 직접 고칠 때는 다음 규칙을 지킨다.
- XML은 lxml로 파싱해서 고친다. 문자열 치환(replace, re.sub)으로 조작하지 않는다.
- 텍스트를 바꾼 `<hp:p>`에서는 `<linesegarray>`를 반드시 지운다.

### 4. 담당자 표와 배포일

담당자 표는 양식에 같은 부서 담당자의 성명과 전화번호가 이미 있으면 그대로 둔다. 비어 있거나 다른 부서 것이면 아는 직위명만 채우고, 성명은 ○○○, 전화번호는 054)679-○○○○로 남긴 뒤 확인을 요청한다.

배포일자는 실제 배포 예정일로 넣고 요일을 함께 적는다(예: 10. 7.(수)). 사용자가 날짜를 주지 않았으면 다음 근무일로 넣고, 그렇게 가정했다고 알린다.

양식에 서체 안내 문구("(HY헤드라인M 20 파란색)" 등)가 있으면 지운다.

### 5. 검증 한계

이 스크립트로는 한글 화면 렌더링까지 확인할 수 없다. 본문 글자 모양을 통일했기 때문에 줄이 넘어가는 위치가 원본과 다를 수 있으니, 한글에서 한 번 열어 확인하라고 알린다.

## 결과 보고

완성된 파일을 전달하고, 바꾼 내용과 그대로 둔 것, 확인이 필요한 항목을 나눠 적는다. 확인 필요 항목에는 다음을 넣는다.
- 배포일자(가정했다면 그 사실)
- 명칭과 사업명 표기의 확정 여부
- 준공·개관 같은 시점 표현이 배포일 기준 시제와 맞는지
- 운영 주체의 확정 여부와 단체 정식 명칭
- 관계자 코멘트의 발언자와 문구
- 검증되지 않은 수치, 업종 구성, 담당자 정보
- 원자료끼리 설명이 어긋나는 부분과 위치·주소의 출처
