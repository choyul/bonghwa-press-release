# 봉화군 보도자료 작성 기준

## 언제 쓰나

다음 요청에 발동한다.
- 보도자료 초안을 쓰거나 다듬어 달라는 요청
- 발표덱·기획안·용역 산출물 같은 원자료를 보도자료로 요약해 달라는 요청
- 공보팀 제출용 양식(hwp 또는 hwpx)을 채워 달라는 요청
- 기존 보도자료 문안을 고쳐 달라는 요청

## 작업 순서

1. 원자료를 읽는다(아래 "원자료 요약").
2. 보도자료 초안을 대화창에 먼저 보여 주고, 확인이 필요한 항목을 따로 나눠 적는다.
3. 초안을 봉화군 보도자료 양식(hwpx)에 채워 파일로 내려 준다(아래 "양식 채우기"). 사용자가 양식을 따로 주지 않아도 이 스킬에 들어 있는 기본 양식으로 바로 만든다. 사용자가 양식을 주면 그 양식을 우선한다.
4. 담당자 표(담당부서·작성자·실무자의 직위·성명·전화)를 모르면 한 번 묻는다. 답이 없으면 ○○○로 남겨 두고 확인 필요 항목에 적는다.

## 원자료 요약

첨부 파일은 실제로 열어서 읽은 내용만 쓴다. pptx는 텍스트를 뽑고, 필요하면 이미지로 렌더링해 장표 구조를 확인한다. PDF는 전문을 뽑은 뒤 핵심 쪽만 이미지로 확인한다.

원자료에서 기사에 쓸 사실(무엇을, 언제, 어디서, 규모, 운영 방식, 일정)을 먼저 추린다. 장표의 소제목이나 "SO WHAT" 같은 내부 보고용 문구는 기사 문장으로 바꿔 쓴다.

다음 항목은 원자료에 있어도 기사에서 뺀다.
- 공개 시점이 걸린 내용: 원자료에 "승인 이후 공개", "확정 전", "검토본", "판매가 미정"처럼 적힌 것
- 기준 시점이나 출처가 없는 통계(인구 수치 등)
- 용역사명, 참여 업체 상호, 개인 실명

원자료끼리 설명이 어긋나면 하나를 임의로 고르지 않고 확인 필요 항목에 적는다. 같은 시설의 준공 시기나 면적이 자료마다 다른 경우가 그렇다. 특정 시설 하나를 다룬 자료의 설명을 여러 시설 전체로 넓혀 쓸 때도 그 사실을 알린다.

시설의 주소나 위치를 넣을 때는 출처(기사, 공고, 대장)를 확인하고, 계획 단계 자료라면 실제 주소와 다를 수 있다고 알린다.

## 문체

신문 기사체(평서형 종결: `~했다`, `~한다`, `~할 계획이다`)로 쓴다. 공문 경어체(`~합니다`)는 쓰지 않는다.

"함께 만들어가는", "~의 여정", "새로운 가치를 창출", "지속 가능한 미래" 같은 AI식·홍보식 상투어는 쓰지 않는다. 담당 주무관이 실제로 쓰는 표현으로 쓴다.

사실을 포장하지 말고 그대로 쓴다. "이름 체계로 정리했다", "한 계열로 묶었다", "성격을 드러냈다", "대상은 ~로"처럼 사실을 한 번 더 해석하거나 돌려 말하는 표현 대신, 무엇을 무엇으로 정했는지 직접 쓴다.
- 고치기 전: 대상은 해오름센터와 내성그린생활지원센터, 솔향센터로, 군은 이들의 이름을 … 정해 한 계열로 묶었으며
- 고친 후: 해오름센터는 ‘발효사이’, 내성그린생활지원센터는 ‘내성사이’, 솔향센터(웰컴센터)는 ‘봉화사이’로 이름을 정했다.

같은 대상에 대한 사실은 연결어미로 이어 쓴다(예: "지상 3층 규모의 ○○는 ~하도록 층을 구성해, ~로 운영된다"). 다만 이름, 위치, 뜻처럼 성격이 다른 사실을 한 문장에 몰아넣지는 않고 문장을 나눈다.

맺음 동사는 쉬운 말로 쓴다. "~라는 성격을 드러냈다"보다 "~공간을 표현했다", "~을 열고 ~는 따로 두지 않을 계획이다"보다 "~을 운영할 계획이다"처럼 쓴다.

하지 않는 일("시설별 홈페이지는 따로 두지 않는다")처럼 내부 운영 방침에 가까운 부정형 정보는 빼고, 할 일만 쓴다.

나열에서 같은 단어가 겹치면 하나를 뺀다(예: "작가 작업실 … 작업실과 스테이" → "작업실과 스테이").

본문 문단 앞에 □ 등 글머리표를 붙이지 않는다. 양식 안내문에 글머리표를 쓰라고 적혀 있어도 붙이지 않는다.

인용부호는 양식의 기존 문안처럼 둥근 따옴표(‘ ’, “ ”)를 쓴다.

## 구조

제목 → 부제 → 리드 문단 → 본문 → 관계자 코멘트 순서로 쓴다.

제목은 "봉화군, ~" 형식으로 한 줄에 쓴다.

부제는 앞뒤 하이픈 없이 핵심 두 가지를 쉼표로 이어 짧게 쓴다(예: "발효사이·내성사이·봉화사이, 12월 통합 플랫폼 ‘봉화사이로’ 개설"). 위치나 거리 같은 부가 정보는 부제에 넣지 않고 본문으로 보낸다.

리드 문단은 "봉화군은 ~했다고 밝혔다." 형식의 한 문장으로 쓴다. 주어는 "봉화군은"이고, 무엇을 했는지를 결과까지 구체적으로 쓴다. 정한 이름, 시작한 사업, 선정된 대상처럼 실제 결과를 문장 안에 넣고, "~로 정리했다", "~에 나섰다"처럼 뭉뚱그리지 않는다.
- 고치기 전: 봉화군이 봉화읍 내성리 일대에 조성 중인 거점시설 세 곳의 이름을 ‘사이’로 끝나는 하나의 이름 체계로 정리했다.
- 고친 후: 봉화군은 봉화읍 내성리 일대에 조성 중인 도시재생 거점시설 세 곳의 명칭을 각각 ‘발효사이’, ‘내성사이’, ‘봉화사이’로 정했다고 밝혔다.

리드에서 "밝혔다"로 출처를 밝혔으면 본문에서는 "~했다고 설명했다"를 되풀이하지 않고 사실로 쓴다.

이어지는 문단은 대상·기간·방식, 참여 전문가, 세부 지원 내용, 상위 사업과의 관계 순으로 전개한다. 시설을 소개하는 기사라면 다음 순서로 쓴다.
1. 이름(기존 명칭 → 새 이름), 위치 관계, 이름의 뜻
2. 시설별 소개(시설당 한 문단)
3. 운영 주체와 일정
4. 연계 플랫폼

여러 시설이나 사업을 문단마다 나란히 소개할 때는 각 문단에서 대상 이름 앞에 △를 붙인다(예: "내성리 217-5번지 일원에 지상 3층 규모로 들어서는 △발효사이(옛 해오름센터)는 …").

본문은 관계자 코멘트를 빼고 6문단 안팎으로 제한한다. 같은 사실을 두 문단에서 반복하지 않는다. "전문가가 매장을 방문한다", "의견을 듣고 과제를 도출한다" 같은 문장이 여러 문단에 흩어져 있으면 한 곳으로 합친다.

마지막 문단의 일반론("앞으로도 ~ 지속할 방침이다", "지역민에게는 ~ 관광객에게는 ~")은 지운다. 기자가 잘라내는 부분이고 사업 정보가 없다.

관계자 코멘트의 발언자는 "봉화군 관계자는"으로 흐리지 않는다. 소관 부서장의 성명과 직위를 "○○○ 도시계획과장은" 형식(성명 → 직위 → 은)으로 쓴다. 성명은 양식 담당자 표의 담당부서 줄에서 가져온다.

준공·개소·개관 같은 시점 표현은 배포일 기준 시제로 맞춘다. 배포일에 이미 지난 일이면 "~했다", 아직이면 "~할 예정이다"로 쓰고, 일정이 바뀔 가능성이 있으면 알린다.

## 실명·수치 처리

참여 업체 상호는 쓰지 않는다. "관내 카페·음식점 5개소"처럼 업종과 개소 수로 쓴다. 업종 구성을 모르면 추정하지 말고 확인 필요 항목으로 남긴다.

외부 전문가·강사의 성명, 소속 회사명, 직위는 쓰지 않는다. "식품·외식 대기업에서 19년간 메뉴개발을 담당한 전문가"처럼 경력의 성격만 남긴다. 다만 익명화하면서 전문성의 근거까지 사라지면 안 되므로, 그 경력이 이번 사업과 어떻게 연결되는지 한 문장을 덧붙인다. 이 익명화 규칙은 외부 인물에만 적용하며, 코멘트를 하는 군 공무원은 위 "구조"의 규칙대로 실명과 직위를 쓴다.

위탁 운영 단체명은 확정 전이면 "마을관리사회적협동조합"처럼 일반 표현으로 쓰고, 정식 명칭을 써도 되는지 확인을 요청한다.

용역사나 업체가 제공한 수치(개발 건수, 실적 등)는 검증 근거가 없으면 넣지 않는다. 꼭 넣어야 하면 근거 자료를 확보해야 한다고 함께 알린다.

관계자 코멘트 문구는 직접 지어 넣되, 예시임을 밝히고 발언자와 문구를 확정해야 한다고 알린다.

## 사업명 표기

봉화군 로컬 브랜드는 '찐로컬'로 붙여 쓴다. 공모요강이나 계약서상 정식 명칭이 다를 수 있으므로, 표기가 갈리면 확인을 요청한다. 브랜딩 검수 전인 시설 명칭은 표기가 확정됐는지 확인 필요 항목에 넣는다.

## 양식 채우기

### 0. 스크립트와 기본 양식 확보

이 스킬 폴더에는 다음 두 파일이 들어 있다.
- `scripts/fill_hwpx.py`: 양식 채우기 스크립트
- `templates/press_release_template.hwpx`: 봉화군 보도자료 기본 양식. 머리 표(보도자료 표제, 공보 이메일, 담당자 표, "군정홍보에 많은 관심과 협조 감사드립니다."), 제목·부제 칸, 본문 서식(휴먼명조 15pt)이 들어 있고 내용은 ○○○로 비어 있다.

스킬을 저장소 주소로 설치해 SKILL.md만 저장된 경우에는 두 파일이 없다. 그럴 때는 작업 폴더에 공개 저장소에서 내려받는다. 스크립트는 같은 폴더 기준 `../templates/press_release_template.hwpx`를 기본 양식으로 찾으므로, 폴더 구조를 그대로 맞춘다.

```bash
B=https://raw.githubusercontent.com/choyul/bonghwa-press-release/main/skill/bonghwa-press-release
mkdir -p press/scripts press/templates
curl -fsSL -o press/scripts/fill_hwpx.py "$B/scripts/fill_hwpx.py"
curl -fsSL -o press/templates/press_release_template.hwpx "$B/templates/press_release_template.hwpx"
```

curl이 막혀 있으면 `git clone --depth 1 https://github.com/choyul/bonghwa-press-release.git`으로 받는다. 이때 스킬 폴더는 `bonghwa-press-release/skill/bonghwa-press-release/`이다.

내려받기도 실패하면 네트워크 제한 때문일 가능성이 크다. 같은 방법을 다시 시도하지 않는다. 사용자에게 다음 두 가지 중 하나를 안내하고, 그동안 보도자료 초안과 양식 채우기용 JSON까지는 완성해 준다.
- 저장소의 `dist/bonghwa-press-release-skill.zip`을 스킬로 다시 설치한다.
- 설치 안내 페이지(https://choyul.github.io/bonghwa-press-release/)에서 스크립트와 기본 양식을 내려받아 대화에 첨부한다.

### 1. 어떤 양식을 쓸지 정하기

- **사용자가 양식을 주지 않은 경우:** 기본 양식을 쓴다. `--template`을 생략하면 된다.
- **사용자가 .hwpx 양식을 준 경우:** 그 양식을 `--template`으로 넘긴다.
- **사용자가 구형 .hwp 양식을 준 경우:** 직접 고치지 않고 .hwpx로 바꾼 뒤 쓴다. 한글이 있으면 [다른 이름으로 저장 → 파일 형식 HWPX]로 저장한다. 한글이 없는 환경(Java 17+, Maven, git 필요)이면 `tools/hwp2hwpx/convert.sh 양식.hwp 양식.hwpx`로 바꾼다. 변환이 어려우면 기본 양식으로 만들고 그렇게 했다고 알린다.

결과물은 .hwpx이며 한글에서 그대로 열린다. .hwp가 필요하면 한글에서 다시 저장하면 된다고 알린다.

### 2. 내용 JSON 만들기

```json
{
  "date": "10. 7.(수)",
  "title": "봉화군, ○○ 착수",
  "subtitle": "○○, ○○",
  "contacts": [
    {"직위": "도시계획과장", "성명": "○○○", "전화": "054)679-○○○○"},
    {"직위": "도시재생팀장", "성명": "○○○", "전화": "054)679-○○○○"},
    {"직위": "실무자", "성명": "○○○", "전화": "054)679-○○○○"}
  ],
  "body": ["리드 문단", "둘째 문단", "…", "관계자 코멘트"]
}
```

- `contacts`는 양식 담당자 표의 담당부서·작성자·실무자 줄 순서다. 셋째 줄의 직위 자리는 보통 "실무자"다.
- 사용자가 준 양식에 담당자 정보가 이미 맞게 들어 있으면 `contacts`를 빼고, 양식의 담당자 표를 그대로 둔다.
- 기본 양식을 쓸 때 담당자를 모르면 ○○○를 그대로 넣는다.
- 배포일자는 실제 배포 예정일과 요일로 적는다(예: 10. 7.(수)). 사용자가 날짜를 주지 않았으면 다음 근무일로 넣고 가정했다고 알린다.
- `body`에는 빈 줄 없이 문단만 순서대로 넣는다. 스크립트가 문단 사이 빈 줄을 넣는다.

### 3. 파일 만들기

```bash
pip install lxml
# 기본 양식으로 만들기
python scripts/fill_hwpx.py --content 내용.json --out 보도자료_주제.hwpx
# 사용자가 준 양식으로 만들기
python scripts/fill_hwpx.py --template 양식.hwpx --content 내용.json --out 보도자료_주제.hwpx
```

실행이 끝나면 결과 파일의 담당자·배포일자·제목·부제·본문 목록이 출력된다. 이 출력을 확인하고, 사용자에게 파일을 내려 준다. 양식 구조가 의심스러우면 먼저 `--template 양식.hwpx --dump`로 확인한다. 스크립트는 "군정홍보에 많은 관심과 협조 감사드립니다." 다음의 두 문단을 제목과 부제로 본다.

스크립트가 처리하는 일은 다음과 같다.
- 담당자 표를 채우고, 직위 길이와 상관없이 성명이 같은 위치에서 시작하도록 공백을 맞춘다.
- 본문 문단 수에 맞춰 문단을 늘리거나 줄이고, 빈 문단을 사이사이 넣어 원본 간격을 유지한다.
- 본문은 양식의 기본 본문 글자 모양 하나로 통일한다.
- 텍스트를 바꾼 문단마다 줄 배치 캐시(linesegarray)를 지워 글자 겹침을 막는다.
- 한글이 저장해 둔 미리보기(썸네일·미리보기 텍스트)를 새 내용으로 바꿔, 이전 문서 내용이 남지 않게 한다.
- mimetype을 비압축으로 맨 앞에 넣어 다시 묶은 뒤, zip 손상 여부를 검사한다.

스크립트를 쓰지 않고 직접 고칠 때는 XML을 lxml로 파싱해서 고치고(문자열 치환 금지), 텍스트를 바꾼 `<hp:p>`에서 `<linesegarray>`를 반드시 지운다.

양식에 서체 안내 문구("(HY헤드라인M 20 파란색)" 등)가 있으면 지운다.

### 4. 검증 한계

이 스크립트로는 한글 화면 렌더링까지 확인할 수 없다. 본문 글자 모양을 통일했기 때문에 줄이 넘어가는 위치가 원본과 다를 수 있으니, 한글에서 한 번 열어 확인하라고 알린다.

## 결과 보고

완성된 파일을 전달하고, 바꾼 내용과 그대로 둔 것, 확인이 필요한 항목을 나눠 적는다. 확인 필요 항목에는 다음을 넣는다.
- 배포일자(가정했다면 그 사실)
- 명칭과 사업명 표기의 확정 여부
- 준공·개관 같은 시점 표현이 배포일 기준 시제와 맞는지
- 운영 주체의 확정 여부와 단체 정식 명칭
- 관계자 코멘트의 발언자와 문구
- 검증되지 않은 수치, 업종 구성, 담당자 정보
- 원자료끼리 설명이 어긋나는 부분과 위치·주소의 출처
